# 🚀 Полный разбор проекта FSocial Media Downloader

## 1. Обзор проекта
**FSocial Media Downloader** — это высоконагруженный Telegram-бот для скачивания медиа (видео, аудио) из популярных социальных сетей (YouTube, Spotify, SoundCloud, TikTok, Instagram, Pinterest). Проект написан на **Rust** и спроектирован с упором на отказоустойчивость, бесконечную масштабируемость и высокую скорость работы.

Основная идея проекта — разделить прием сообщений от пользователей (Gateway) и тяжелую работу по скачиванию файлов (Worker) с помощью брокера сообщений (NATS).

---

## 2. Архитектура и Инфраструктура
Проект использует микросервисную архитектуру. Код разделен на 3 основных крейта (Cargo Workspace):
1. `common` — общие структуры данных и модели.
2. `gateway` — шлюз, общающийся с Telegram.
3. `worker` — рабочий узел, выполняющий скачивание.

### Инфраструктурные зависимости:
*   **Telegram Local Bot API Server**: Позволяет обходить лимиты публичного API Telegram (50 МБ) и отправлять файлы размером до 2 ГБ.
*   **NATS JetStream**: Высокопроизводительный брокер сообщений. Используется для очередей задач (Free и Premium очереди). Гарантирует доставку задач (WorkQueue).
*   **Redis**: Используется для кэширования (чтобы не скачивать одно и то же видео дважды), хранения состояний (State Machine) пользователей и лимитов (Rate Limiting).
*   **PostgreSQL**: Используется для хранения долгосрочных данных профилей пользователей (хотя в текущем коде активнее используется Redis).
*   **yt-dlp + FFmpeg**: Консольные утилиты, выступающие "движком" для скачивания контента из сетей и его конвертации/склейки.

## 3. Подробный разбор компонентов (Crates)

### 📦 `common` (Общий код)
Содержит DTO (Data Transfer Objects), которые курсируют между сервисами:
*   **`models.rs`**: Основные модели:
    *   `DownloadTask`: Задача на скачивание. Содержит URL, платформу, качество, ID чата и флаг `is_premium`.
    *   `TaskResult` / `TaskStatus`: Статус выполнения задачи (Progress, Completed, Failed, PlaylistProgress).
    *   `Quality`: Перечисление всех уровней качества (от Audio128 до Video4K). Содержит логику для генерации аргументов для `yt-dlp` (`ytdlp_format()`) и умного даунгрейда (`downgrade()`).
*   **`config.rs`**: Чтение конфигурации из переменных окружения (токены, пути к ffmpeg, лимиты).

### 🚪 `gateway` (Шлюз Telegram)
Сердце взаимодействия с пользователем, написано на фреймворке `teloxide`.
*   **`main.rs`**: Настраивает пайплайн обработки сообщений (dptree). Регистрирует команды, инлайн-запросы, коллбеки и платежи (Telegram Stars).
*   **`handlers/`**: Обработчики разных событий (команды, инлайн-кнопки для выбора качества, платежи, проверка состояния).
*   **`nats_client.rs`**: Клиент для публикации задач в NATS. При отправке ссылки шлюз формирует `DownloadTask` и кладет его в стрим `DOWNLOAD_QUEUE`.
*   **`nats_listener.rs`**: Фоновый процесс, который слушает ответы от воркеров (темы `tasks.result` и `tasks.progress`). Когда воркер скачал файл, Gateway берет его путь (из Shared Volume) и отправляет пользователю через Telegram API.

### ⚙️ `worker` (Рабочие узлы)
Выполняет всю грязную работу. Воркеров может быть запущено сколько угодно (горизонтальное масштабирование).
*   **`nats_consumer.rs`**: Цикл получения задач из NATS (Pull Consumer). Поддерживает приоритеты: сначала пытается взять задачу из Premium-очереди, если там пусто — берет из Free-очереди.
*   **Асинхронная обработка плейлистов**: Воркер может получать плейлист и запускать скачивание нескольких треков/видео параллельно с помощью `futures::stream::buffer_unordered`.
*   **`media/ytdlp.rs`**: Обвязка над утилитой `yt-dlp`. Запускает процесс через `tokio::process::Command`, читает его stdout для парсинга прогресса (через regex) и отправляет проценты загрузки обратно в Gateway.
*   **Умный даунгрейд**: Если скачанный файл превышает лимит (2 ГБ для Local сервера или 50 МБ для облака), воркер удаляет его, автоматически понижает качество в `DownloadTask` и пробует скачать заново!
*   **`audio/spotify.rs` & `audio/tagger.rs`**: Специальная логика для Spotify. Парсит метаданные трека через API Spotify (или скрапинг), скачивает аудио с YouTube Music, а затем с помощью библиотеки `lofty` вшивает обложку, автора, название и альбом прямо в MP3-файл (ID3v2 теги).

## 4. Жизненный цикл одного скачивания (Data Flow)
1. **Пользователь** отправляет ссылку (например, YouTube) боту.
2. **Gateway** ловит ссылку (через `url_parser`), отправляет запрос `info` воркеру для получения списка доступного качества.
3. **Gateway** показывает пользователю Inline-клавиатуру с выбором качества (размеры генерируются или оцениваются на лету).
4. **Пользователь** нажимает кнопку качества. **Gateway** создает `DownloadTask` и отправляет его в NATS (в Premium или Free топик, в зависимости от профиля).
5. **Worker** (один из свободных) берет задачу. Отправляет в NATS статус "Начинаю загрузку...".
6. **Worker** вызывает `yt-dlp`, парсит прогресс и шлет события `Progress`.
7. **Gateway** ловит события прогресса и редактирует сообщение в Telegram (Progress Bar + ETA).
8. **Worker** завершает скачивание. Сохраняет файл в папку, доступную Telegram Local API Server (через Docker Volume). Отправляет `TaskResult::Completed` с путем к файлу в NATS.
9. **Gateway** получает результат, делает запрос к Telegram Local API Server на отправку файла из кэша/volume и удаляет сообщение с прогрессом.

## 5. Продвинутые фичи проекта

*   **Монетизация (Telegram Stars)**: Бот нативно поддерживает оплату через Telegram. Premium-пользователи получают свои задачи в отдельную очередь NATS (`tasks.download.premium`), которую воркеры обрабатывают в первую очередь.
*   **Rate Limiting & Статистика (Redis)**: Учитывается количество скачанных байт и файлов за день.
*   **Умное кэширование**: Успешно загруженные файлы получают уникальный `cache_key` (основанный на URL и качестве). При повторном запросе бот мгновенно отправит файл по Telegram `file_id`.
*   **Inline Mode**: Можно использовать бота в любом чате (`@bot_name https://...`).
*   **Поддержка прокси**: В `worker` встроена ротация прокси-серверов (`proxy.rs`) для обхода блокировок со стороны YouTube.

## 6. Как это разворачивается (Deployment)
Проект максимально контейнеризирован. В корне есть `Dockerfile.gateway`, `Dockerfile.worker` и `docker-compose.yml`.
Для запуска всей инфраструктуры достаточно:
```bash
docker compose up -d --build
```
Если бот становится популярным и начинает тормозить, можно добавить мощности одной командой (увеличить количество воркеров):
```bash
docker compose up -d --scale worker=10
```

## Итог
Это **очень качественный, production-ready** проект. Использование Rust гарантирует низкое потребление памяти и отсутствие утечек, NATS дает идеальную балансировку нагрузки, а Teloxide отлично справляется с асинхронным Telegram API. Архитектура построена так, что бот может без проблем обслуживать десятки тысяч запросов в секунду при наличии серверов для запуска достаточного количества worker'ов.
